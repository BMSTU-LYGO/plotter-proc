# UPD_Plotter_21 — натуральность почерка и вариативность букв

## Цель

Убрать ощущение «компьютерного шрифта»: буквы, слова и строки должны немного отличаться друг от друга, но оставаться читаемыми и нормально соединяться.

Основные изменения:

* наклон букв;
* высота;
* ширина;
* небольшое изменение положения;
* визуальная толщина штриха;
* изменение ширины слова целиком;
* плавная вариативность внутри строки, а не случайный шум каждой буквы.

---

# Правила для Codex

1. Работать в текущей ветке, новую не создавать.
2. Не делать полный аудит проекта.
3. Читать только файлы текущей задачи.
4. Не ломать существующий layout, соединения букв и `SuperFast`.
5. Все новые параметры вынести в существующий config.
6. Выполнять **по 2 пункта → коммит**.
7. Коммиты:

```text

```

8. После каждого пункта писать в чат **одно короткое предложение**.
9. Не писать diff и длинные отчёты.
10. Запускать только релевантные тесты.
11. После `21-6` остановиться.

# Пункт 1. Сделать единую модель вариативности почерка

Сейчас любые случайные изменения букв должны управляться из одного места, а не набором независимых random-вызовов.

Добавить конфигурацию примерно такого смысла:

```yaml
handwriting:
  enabled: true
  seed: 123

  letter:
    slant: ...
    height: ...
    width: ...
    y_offset: ...

  word:
    width: ...

  line:
    drift: ...
```

Точные имена подстроить под существующий config.

### Требования

* один `seed` должен давать одинаковый результат;
* другой `seed` — другой вариант почерка;
* `enabled: false` должен сохранять старое поведение;
* все диапазоны вариаций ограничить;
* не использовать хаотический random непосредственно в разных стадиях pipeline.

### Результат

Есть единый контролируемый генератор вариаций, от которого дальше зависят буквы, слова и строки.

# Пункт 2. Реально изменять геометрию отдельных букв

Для каждой буквы добавить небольшие индивидуальные преобразования.

Минимум:

```text
наклон
высота
ширина
небольшой Y-offset
```

Применять преобразование к геометрии glyph, а не только менять расстояние между буквами.

Концептуально:

```text
original glyph
     ↓
scale X
scale Y
shear X
small Y offset
     ↓
modified glyph
```

## Ограничения

Изменения должны быть небольшими.

Например условно:

```text
height: 0.94–1.06
width: 0.94–1.06
slant: небольшой диапазон
```

Конкретные значения подобрать по текущему масштабу.

### Очень важно

После изменения буквы должны сохраняться:

* точки входа/выхода;
* соединение с соседними буквами;
* baseline;
* читаемость.

Не должно получаться:

```text
буква изменилась
→ соединение со следующей буквой разорвалось
```

# Пункт 3. Добавить изменение ширины слова целиком

Нельзя получать натуральность только изменением каждой буквы.

Добавить отдельную вариацию:

```text
word_width_factor
```

Она должна применяться **ко всему слову после формирования его букв**.

Например:

```text
КОМПЬЮТЕР
```

в одном месте может быть чуть уже:

```text
0.97 × width
```

а в другом чуть шире:

```text
1.04 × width
```

---

## Что менять

Масштабировать X-координаты относительно начала или центра слова:

```text
word paths
connectors
letter positions
```

При этом высота слова не должна изменяться.

---

## Не делать

Не подменять это обычным:

```text
letter_spacing += random
```

Изменение ширины слова должно выглядеть как изменение манеры письма, а не как случайные пробелы между буквами.

---

# Пункт 4. Сделать вариативность плавной, а не случайной

Главная проблема полностью случайного изменения каждой буквы:

```text
A: высокий наклон
Б: наклон в другую сторону
В: очень широкая
Г: снова узкая
```

Это выглядит искусственно.

Нужно добавить **коррелированную вариативность**.

---

## Принцип

У строки или участка текста должно быть общее состояние:

```text
current_slant
current_height
current_width
```

Оно постепенно меняется:

```text
буква 1 → 0.99
буква 2 → 1.00
буква 3 → 1.01
буква 4 → 1.015
```

а не:

```text
0.94
1.06
0.95
1.05
```

---

## Добавить уровни вариаций

Использовать минимум:

```text
document/base style
        ↓
line variation
        ↓
word variation
        ↓
small letter variation
```

То есть большая часть стиля одинакова, а мелкие отклонения накладываются сверху.

### Результат

Текст начинает выглядеть как один человек, который пишет немного по-разному, а не как набор случайно деформированных символов.

# Пункт 5. Добавить вариативность визуальной толщины штриха

Физическая толщина линии в основном определяется ручкой, поэтому программно её можно менять только ограниченно.

Не пытаться превращать каждую линию в сложный контур.

Добавить лёгкий опциональный режим визуальной толщины.

## Вариант реализации

Для отдельных штрихов разрешить небольшой повторный проход или очень малое смещение повторного штриха:

```text
normal stroke
+
optional tiny retrace/offset
```

Только если это действительно визуально увеличивает толщину.

---

## Ограничения

* вариация должна быть небольшой;
* не создавать заметные двойные линии;
* не увеличивать резко количество G-code;
* не портить соединения;
* не применять ко всем буквам одинаково.

### Важно для скорости

В `SuperFast` этот эффект должен быть:

```text
disabled
```

либо максимально ограничен.

Скорость имеет приоритет над искусственной толщиной.

Таким образом:

```text
normal/quality → thickness variation allowed
superfast      → minimum/no thickness variation
```

# Пункт 6. Добавить ограничения натуральности и финальную интеграцию

Все эффекты предыдущих пунктов должны работать вместе и не разрушать текст.

Добавить единый этап проверки после handwritten transforms.

Проверять:

```text
glyph bounds
word bounds
line bounds
connectors
page bounds
keep-out zones
```

---

## Ограничивать экстремальные сочетания

Например если одновременно получились:

```text
широкая буква
+
широкое слово
+
большой наклон
```

итог не должен выходить за разумный диапазон.

Нужен clamp финального результата.

---

## Не допускать накопления смещения

Нельзя, чтобы небольшая вариация каждой буквы приводила к:

```text
начало строки: нормально
конец строки: +20 мм
```

Финальная ширина слова и строки должна учитываться layout engine.

---

## Проверить разные seed

Прогнать один небольшой русский fixture минимум с несколькими seed.

Проверить:

* результат действительно различается;
* одинаковый seed воспроизводится;
* буквы читаемы;
* слова не разваливаются;
* соединения сохранены;
* строки не выходят за страницу;
* `SuperFast` продолжает работать;
* `grid` и A5 keep-out из `UPD_Plotter_20` не ломаются.

Не делать тяжёлый визуальный benchmark.

---

## Итоговый результат

После `UPD_Plotter_21` два одинаковых слова не обязаны выглядеть пиксель-в-пиксель одинаково:

```text
Привет ... Привет
```

должны иметь небольшие различия в:

```text
наклоне
ширине
высоте
форме/положении букв
общей ширине слова
```

но при этом визуально оставаться **одним и тем же почерком**.
